## 4. Rules

- **Router input precision unchanged from k3-v08-2.** FP32 router input at T ≤ 8 (the boundary writes it, as stock),
  BF16 above. This was verified on the box (`tools/box/router_input_check.py`):
  - SGLang's default JIT boundary writes the FP32 normalized value *before* BF16 rounding;
  - it differs from the BF16 FFN input upcast by up to 1.5e-2;
  - only SGLang's Triton and native paths upcast the BF16 output;
  - so the v08-2 fix was needed.
- **The cluster boundaries are SGLang's own kernel**, with the same inputs and outputs as the module call (FP32
  router input included).
- **PDL.** Only the tail uses it, and it waits before reading any output of an earlier kernel. K2A v3.1 keeps its own
  internal chain; its first kernel is launched without PDL.

## 5. Not done, and why (measured or estimated)

- **Early-release PDL between the big kernels.** qkv, o, pooler and unpooler are cuBLAS (PyTorch launches them
  without the PDL attribute); K1 and K2A v3.1 are verbatim slices; the boundaries are SGLang's and already PDL-aware.
  Only the tail is ours on the main stream, and it now uses PDL (+0.25%).
- **K1 v5 (wgmma) at verify full.** Estimated about +0.15% on the problem: 1.06× on the attention alone at verify 32
  full, which is 2% of that load. Not built, because it adds a third K1 build (about 40 s of prepare).
- **Unpooler at T ≥ 128 vs stock.** It is now within about 1.5 µs (26.6 vs 25.1 at T = 256, `box_out/lb9_analysis.md`).
  Not pursued.
- **Merging the remaining small kernels** (at T ≤ 8: zero-fill before the ffn boundary; at L = 8: qk-norm + store).
  The staging copy is there because the FusedQKNorm kernel skips cache row 0, which is live here. A direct-write
  fusion needs a new kernel: about 3 µs on the 8-token verify shapes, ~0.5% of the problem.
