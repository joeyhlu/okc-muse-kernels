## 2. Direct-store QK-norm on the L = 8 path

- **What it replaces.** SGLang's Triton QK-norm kernel already writes the FP8 K/V rows, but it skips cache row 0
  (SGLang's CUDA-graph padding slot). Row 0 is live here, so v07–v09 staged the rows and copied them with
  `store_cache`.
- **What v10 does.** `_v10_qk_fwd_kernel` is that kernel with only the row-0 mask removed. It runs with the same
  launch (grid, block_m, warps, PDL) and writes straight into the cache.
- **Self-test:** q and every cache byte are bit-identical to the staging path at T = 5/8/128/256, with and without
  RoPE, with cache_loc including row 0.
- **In-layer A/B** (`box_out/ab_v10a.log`): verify 1 +1.0–1.1%, verify 16/32 +0.1–0.3%, about +0.1% on the problem.
