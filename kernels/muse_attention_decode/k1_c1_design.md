## 1. What changes

Base: `k1_v4.py`. k3_v11 (generated by gen_k3_v11 through gen_k3_v08 with `USE_K1_V4`) carries K1 v4. Its
`K1_CUDA_SRC` / `K1_CPP_SRC` are byte-identical to `k1_v4.py`'s `CUDA_SRC` / `CPP_SRC`, checked on this branch. On
sliding L=1, K1 v4 uses split-KV with the batched last-CTA merge from lab.md row "k1-v4". `k1_v9c.py` is a copy of
k1_v4 in which only the split/merge path changes.

| piece | v4 (kept, selectable in the same build) | v9c cluster path (`cs > 0`) |
|---|---|---|
| launch | `<<<(Gx = SMs·cps / hp, Hkv/2)>>>`, ~132 CTAs | `cudaLaunchKernelEx` + `cudaLaunchAttributeClusterDimension (CS,1,1)`, grid `(B·CS, Hkv/2)`, one cluster per (request, head pair). CS > 8 sets `cudaFuncAttributeNonPortableClusterSizeAllowed` |
| plan | `plan_C`, a warp binary search over all requests, then `plan_find`, a prefix scan | request `b = blockIdx.x / CS`, split = rank, `C_b = max(min_chunk, ⌈nt/CS⌉)`, `S_b = ⌈nt/C_b⌉ ≤ CS`, the same balanced boundaries. Ranks ≥ S_b are idle |
| partials | every split stores O (16L×64 f32) and lse to global; `__threadfence`; `atomicAdd` on a counter; the last CTA re-fences | O and lse stay in the CTA's own smem (`ost` / `lse_s`, already there in v4) |
| sync | counter + 2 × `MEMBAR.SC.GPU` | `barrier.cluster.arrive.release` / `wait.acquire` (barrier 1) |
| merge | the last CTA merges all 16L rows from L2 | rank r merges rows `[r·16L/S, (r+1)·16L/S)` from its peers' smem: `mapa.shared::cluster` + `ld.shared::cluster.v4.f32` / `.f32`. All S loads of a row are in flight at once (one DSMEM round trip) |
| epilogue | norm-gate + bf16 store | the same code; the gate row and v_scale are loaded **before** barrier 1 (L=1: the gate is loaded at kernel start, 2 registers), because `wait.acquire` invalidates L1 (`CCTL.IVALL`) |
| exit | — | barrier 2: arrive after the CTA's last DSMEM value is consumed, wait at exit. No CTA leaves while a peer may still read its smem |

**Numerics.**
- Per output (row, quad), `merge_cluster` runs `merge_finalize`'s code op for op: online max over batches of UN splits
  in order s = 0..S−1, `ex2` weights, `fmaf` accumulation, `vsc/ws`, half-warp RMS, sigmoid gate.
- It reads the same float32 partial values (smem instead of an L2 copy of smem).
- Whenever the two plans agree, the output is therefore **bit-identical** to v4. They agree on every scored sliding
  shape (emulation §3.1).

**Switches.**
- `K1_CLUSTER` (define, default 1). With `-DK1_CLUSTER=0` the device SASS is **identical to k1_v4's**, modulo
  constant-bank offsets from the two new Params fields. Checked with `ccheck.py --same-sass-as`.
- Host tables:

| setting | default | effect |
|---|---|---|
| `K1_CLUSTER_T` | `{("sliding", 1): True}` | which (kind, L) use the cluster merge |
| `K1_CLUSTER_MAX` | 16 | largest cluster size |
| `K1_CLUSTER_PAD1_T` | sliding L=1 | dynamic smem padded to 120 KB so at most 1 CTA fits per SM, as the measured-best cps=1 does for v4 |
| `K1_C1_RELAX` | 0 | lab: relaxed arrives (see Risks) |

- Per-call lab overrides on `_k1`: `cluster=`, `cs=`, `pad1=`, `relax=`.
- Every other route switch is unchanged: the route, fold, min_chunk, cps and stages tables, FALLBACK, SELF_TEST.

**Cluster size pick (host).**
- `CS = min(16, SMs·cps/(B·hp), ⌈⌈(W−1)/64⌉/min_chunk⌉)`, with CS ≥ 2; otherwise the v4 merge is used.
- Scored sliding L=1: B = 1 / 16 / 32 → CS = 16 / 8 / 4, i.e. grids of 16 / 128 / 128 CTAs. These are exactly v4's
  busy CTAs and splits.
- All B·hp clusters must be co-resident (one wave, by `cudaOccupancyMaxActiveClusters`). If not, the host tries
  unpadded, then CS−1. A size the driver rejects reports 0, so it is never picked.
- The self-test caches every (L, stages, CS, pad) occupancy, so no query happens under graph capture. An uncached
  query under capture means the v4 merge is used for that call.

**Safety (R9).**
- No spin loops are added. `barrier.cluster` is a hardware barrier over CTAs that are guaranteed to be co-scheduled.
- Every CTA of a cluster executes exactly two arrive/wait pairs on every path: active, S_b = 1 (rank 0 alone), and
  idle rank.
- A launch whose cluster shape isn't (CS,1,1) sets `err[0]` and every CTA returns before any barrier.
  `%cluster_nctarank` is launch-uniform, so no CTA is left waiting.

**Self-test.**
- k1_v4's 11 cases × (fold, sep, fold) run unchanged, on the v4 merge.
- Then a cluster stage with 14 cases:
  - CS 2/3/4/8/12/16, padded and unpadded;
  - idle ranks (3..7-tile requests), S_b = 1, window edge, kv_scale 1/64;
  - 8 head pairs (grid y = 8), full layers, L=8.
- A cluster failure only clears `cluster_ok[L]`; the v4 merge is kept. A forced size that can't be launched is skipped.

**Registers** (ptxas 13.0.88, `-O3 -Xptxas=-v`, sm_90 and sm_90a give the same numbers):

| kernel | k1_v4 | k1_v9c |
|---|---|---|
| k1_main<1,4> / <1,6> (routed) | 109 regs, 0 spill | **112 regs, 0 spill** (≤ 128, so 2 CTAs/SM still fit) |
| k1_main<8,4> (unrouted; L=8 lab) | 128 regs, spill 16/20 B; 7 LDL/STL near the tile loop | 128 regs, spill 16/48 B; 5 near the tile loop |
| k1_main<8,3> (not used) | 128, 16/20 B | 128, 28/60 B |
| k1_combine | 40, 8/4 B | 40, 8/4 B (unchanged) |

**SASS of the cluster barriers** (nvcc 13.0, both arches):

| PTX | SASS |
|---|---|
| `barrier.cluster.arrive.release` | `MEMBAR.ALL.GPU; ERRBAR; CGAERRBAR; UCGABAR_ARV` |
| `wait.acquire` | `UCGABAR_WAIT; CCTL.IVALL` |
| `fence.acq_rel.cluster` | the same `MEMBAR.ALL.GPU` |
| `arrive.relaxed` | `UCGABAR_ARV` only |

So the formally ordered (PTX-memory-model) cluster barrier still pays one GPU-scope membar per arrive. There is no
cluster-scope MEMBAR. This is why `K1_C1_RELAX` exists as a lab knob (§5).

## 5. Risks

| risk | likelihood | what we do |
|---|---|---|
| The release arrives' `MEMBAR.ALL.GPU` eat most of the gain | medium | A/B `c1r1` / `c1r3`. Relaxed arrive 1 comes after `__syncthreads()` (the partials are in this SM's smem, which serves the DSMEM reads); relaxed arrive 2 comes after every DSMEM value is consumed. Correct in practice, but not ordered by the PTX memory model, so it is off by default and adopting it is a decision (log it in notes/assumptions.md if adopted). Alternative: an `st.async` push into the merging rank's smem with an mbarrier `complete_tx`, as in FlashMLA's sparse decode. No GPU membar and no second barrier, but it needs a bounded `try_wait` (R9) |
| dec1's 16 CTAs now sit in **one GPC** (v4 spread them over the chip); the per-GPC L2 path may slow the 512 KB KV read | low-medium | Measured by the dec1 row. If it shows, use CS=8 with min_chunk 2 at B=1: 2 clusters, each 8 CTAs × 4 tiles (slower loop), or keep v4 at B=1 via the table |
| The padded 1-CTA/SM launch can't co-schedule all clusters (GPC sizes) | low | The host falls back automatically (unpadded, then CS−1); the self-test prints the occupancy table |
| `cudaLaunchKernelEx` + cluster under stream capture | low | CUDA 12+ supports it; the A/B and the judge clone capture graphs |
| 3 extra registers change the L=1 loop schedule | low | 112 ≤ 128 regs, 0 spill; the `c0` vs `v4` rows measure it |
| Non-power-of-two cluster sizes rejected by the driver | low | Occupancy 0 → not picked. The scored shapes use 16/8/4 |

## 6. L=8 sliding extension (sketch; the code path already exists, lab only)

The cluster path is generic in L. k1_main<8,4> with `cluster=True` compiles and is in the self-test:
- S=8 at min_chunk 4 (CS ≤ 32 tiles / 4);
- 16 rows per rank, one item per thread;
- 8 DSMEM float4 + 8 lse loads per thread in one batch (UN=8).

**Measured problem it removes.** v4's L=8 last-CTA merge takes **20 µs at ver1 sliding** (k1v4_b1.log PROF: s7
22.02 → s6 41.98 µs) and ~13 µs at ver32 (v3 PROF). That is the "L=8 merge pathology" item in k1_v4.md §6. The cluster
merge has no per-batch L2 round trips, so the expected merge cost is ~1 µs.

**What the A/B's L=8 rows measure** (`r1`, `v4`, `c0`, `c1`, `c1r3`, `c1m2`). With v4's slow L=8 tile loop (QK-bound,
~45 clk/key):

| shape | v4 L=8 tile loop ready (s4 max) | expected c1 | rung-1 |
|---|---|---|---|
| ver1 | 19.97 µs | ~21 µs | 18.2 µs |
| ver32 | v3 26.11 µs | ~27 µs | 30.4 µs |

- **ver32 sliding could already win ~3 µs/call** (+0.08% layer; route `("sliding", 8)` for B ≥ 32).
- `c1m2` (min_chunk 2 → 16 two-tile splits at ver1/16) tests a lever that only a cheap merge makes viable. The v4 L=8
  tile loop costs ~1.9 µs per tile at ver1 (s2 7.17 → s3 14.59 for 4 tiles), so halving the tiles per CTA would put ver1
  at ~16–17 µs vs rung-1 18.2.

**The full extension, after B1 (k1_v8f, FA3 wgmma discipline) lands a faster L=8 tile loop:**
1. Keep the wgmma kernel's own epilogue (row = token·8 + head-in-group, h·R8 + …) but write O/l to `ost` [128][64] f32
   and `lse_s` [128] in the drained K/V ring. k1_v5–v8 rings are ≥ 64 KB, enough for 32.5 KB, so smem doesn't grow.
2. Use v9c's cluster plan and `merge_cluster<8>` unchanged.
3. Use min_chunk 2 and CS up to 16 at small B: more splits and shorter tile loops, which the cheap merge allows.
4. Expected: a sliding L=8 call ≈ prologue (s2 ≈ 7–10 µs today, itself a target: 128-row Q prep + 8 new K/V) + 2 tiles
   + ~1 µs merge.
5. Verify-sliding is weighted like verify-full (niche_approaches §0). Reaching rung-1 − 5 µs on ver1/16/32 sliding would
   be worth ~+0.5% layer on top of B1.
